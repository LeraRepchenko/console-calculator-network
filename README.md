\# Console Calculator (Network)



Лабораторная работа №1. Консольный калькулятор с метаобъектами Qt.



\## Вариант 15 (продвинутый уровень)



Калькулятор-сервер (минимальный): TCP-сервер + TCP-клиент.



\## Цель работы



Изучить механизм сигналов и слотов Qt на примере консольного приложения.

Освоить наследование от `QObject`, объявление собственных сигналов и слотов,

установку соединений через `QObject::connect()`, а также работу с

метаобъектной системой Qt (MOC) в консольном режиме без графического интерфейса.



\## Архитектура



Проект состоит из трёх подпроектов:



\- \*\*CalcServer\*\* — TCP-сервер, содержащий класс `Calculator` с логикой.

\- \*\*CalcClient\*\* — TCP-клиент с асинхронным вводом через `QThread`.

\- \*\*CalcTests\*\* — юнит-тесты для класса `Calculator` на базе `QTest`.



\### Схема взаимодействия



```

+-------------+        TCP :5555        +-------------+

|  CalcClient | <---------------------> |  CalcServer |

|  (QObject)  |   "add 5 3\\n"           |  (QObject)  |

|             | --------------------->  |             |

|             |   "RESULT: 8\\n"         |  Calculator |

|             | <---------------------  |  (QObject)  |

+-------------+                         +-------------+

```



\### Паттерны проектирования



\- \*\*Наблюдатель (Observer)\*\* — через сигналы Qt: `Calculator::resultReady`,

&#x20; `Calculator::errorOccurred`. Сервер и тесты подписываются на эти сигналы.

\- \*\*Фасад (Facade)\*\* — класс `Server` предоставляет простой интерфейс для

&#x20; работы с сетью, скрывая детали `Calculator` и `QTcpServer`.

\## Сборка



1\. Открыть `CalculatorNetwork.pro` в Qt Creator.

2\. Собрать все три подпроекта (молоток в левом нижнем углу).

3\. Запустить сервер, затем клиент.



\### Требования



\- Qt 6.11.2 (или совместимая)

\- MinGW 13.1.0 64-bit (или MSVC)

\- qmake

\- Qt Creator 20.0.1 (или новее)



\## Запуск



\### Сервер



Правой кнопкой по `CalcServer` → \*\*Запустить\*\*. Должно появиться:



```

Сервер запущен на порту 5555

```



\### Клиент



Правой кнопкой по `CalcClient` → \*\*Запустить\*\*. Должно появиться:



```

Подключено к серверу.

Введите команду (add/sub/mul/div a b) или quit:

> 

```



\## Команды



| Команда | Описание | Пример |

|---------|----------|--------|

| `add a b` | Сложение | `add 5 3` → `RESULT: 8` |

| `sub a b` | Вычитание | `sub 100 37` → `RESULT: 63` |

| `mul a b` | Умножение | `mul 4 2.5` → `RESULT: 10` |

| `div a b` | Деление (с проверкой нуля) | `div 10 2` → `RESULT: 5` |

| `div a 0` | Деление на ноль | `div 10 0` → `ERROR: деление на ноль невозможно` |

| `quit` | Выход | `quit` → `До свидания!` |



\## Тесты



Запуск через Qt Creator: \*\*Проекты → CalcTests → Запустить\*\*,

или через вкладку \*\*«Тесты» (Tests)\*\* в левой панели.



Тесты проверяют:



\- корректность арифметики (`add`, `sub`, `mul`, `div`);

\- сигнал `resultReady` — излучается после успешного вычисления;

\- деление на ноль — сигнал `errorOccurred`, флаг `hasError()`;

\- сброс флага ошибки после успешной операции.



\### Список тестов



| Тест | Что проверяет |

|------|---------------|

| `testAdd` | Сложение и сигнал `resultReady` |

| `testSubtract` | Вычитание |

| `testMultiply` | Умножение |

| `testDivide` | Деление |

| `testDivideByZero` | Сигнал `errorOccurred` при делении на ноль |

| `testErrorReset` | Сброс ошибки после успешной операции |

\## Особенности реализации



\### Асинхронный ввод в клиенте



На Windows `QSocketNotifier` не работает с консольным вводом.

Поэтому чтение `stdin` вынесено в отдельный поток `InputThread`

(наследник `QThread`), который блокирующе читает строки и излучает

сигнал `lineEntered(QString)`. Главный поток ловит этот сигнал и

отправляет строку на сервер.



\### Кодировка UTF-8



Для корректного отображения русского текста в консоли Windows

в `main.cpp` обоих проектов вызываются:



```cpp

SetConsoleOutputCP(CP\_UTF8);

SetConsoleCP(CP\_UTF8);

```



Плюс `QTextStream` настраивается через `setEncoding(QStringConverter::Utf8)`.



\### Буферизация TCP



TCP — потоковый протокол, команды могут прийти по частям.

В сервере для каждого клиента хранится отдельный буфер `QByteArray`,

и команды разбираются по символу `\\n`.
